### 本日修出的问题

1. **`dataclass` 里 `filters: dict[str, str] = field(...)` 与 `FieldSpec` 的字段名 `field` 撞车**：`TypeError: 'str' object is not callable`。改成 `from dataclasses import field as dc_field`，所有默认值都用 `dc_field(...)`。
2. **剧本解释模板里的 `{rows_total}` 没被替换**：证据脚本为了留证把模型包了一层记录器，而 `explain_result` 只认 `model` 本身有没有 `context`，透过 `inner` 找不到剧本模型，占位符就原样印出来了。加了 `_context_target()` 向下解包（最多 4 层），现在离线解释的数字都是真实统计值。
3. **守门提示语还在说「目标」**：直接复用单元20 的 `validate_goal` 会显示"目标不能为空/至少 4 个字"，而本单元被守的是运营问的那句话。改成自己实现的 `validate_question`（规则一致：非字符串 / 空 / 过短 4 / 超长 200），措辞统一为"问题"。
4. **「三类合计占 75.0%」被判成编造数字**：`allowed_numbers` 只放了每个组的单数与占比，模型把三组相加就被点名。补上占比（各组 ÷ 总行数）与 ≤8 组时枚举出的"若干组相加"合计与占比，核验才既严格又不误伤。
5. **「占 0%」的解释**：`_number_context` 原来只在有分组时算占比，带筛选的计数（如"需要转人工的工单 16 单，占 32 单的 50%"）拿到 0%。补了 `value ÷ rows_total` 分支。
6. **坏值当 0 的均值反而更低的断言写反了**：原以为脏表均值会偏高，实测脏表少了 3 个较大的退款值，162.34 < 干净表 173.25。改成断言"参与金额总和 ≈ 4708 且均值 > 总和 ÷ 32"，这才是"不静默当 0"的正确表达。
7. **全库一起跑时剧本场景偷偷换成了真实模型**：`build_data_model` 默认读 `LLM_PROVIDER`，而别的测试模块会 `load_dotenv()` 把 `.env` 里的 `deepseek` 带进环境，导致 8 项用例在 `discover` 下失败（单跑全过）。测试里统一改用 `offline(script)` helper 显式传 `provider="mock"`。
8. **`source_without_execution` 把 `compile(` 也算进去**：模块里 `re.compile(` 是正则、不是执行入口，误报"发现执行代码"。只查 `eval(` / `exec(` / `__import__(` 三个真正的入口。

12. **客服查不在名下的工单，气泡里弹「请求失败：未找到可访问的工单」**（截图反馈）：跨坐席回 404 是对的，但 `/v1/chat` 把它原样弹给客服，客服只会以为系统坏了。改成对话层给同一句话术（"没找到你能访问的工单 AS23004……可能是号记错了，也可能在别的坐席名下"），`/v1/tickets/{id}` 仍按 HTTP 语义回 404；补一条断言盯着"别人的"和"不存在的"答复去掉编号后完全一致（不泄露归属）。
13. **`python main.py --serve` 报 `[Errno 10048]` 然后 exit 3**（截图反馈）：上一个工作台还开着（调试时起的服务占着 8000）。`serve()` 加端口探测，被占就自动改用 8001 / 8002 / 8021 并打印"原来的端口已被占用"，不再直接退出；补一条测试用随机端口占住再挑端口。
