### 本日修出的问题

1. **角色标记写在 system、数据写在 human，剧本模型只取最后一条就认错角色**：离线剧本模型判断角色要看**全部消息**拼起来的文本（沿用单元20 的 `_joined_text`），生成内容才只看最后一条。
2. **模型调用次数被数重了**：规划那一次在①已计入，执行器又加了一遍 `1 + replans`，正常协作显示 5 次而明细只有 4 项。改成执行阶段只补「重规划」的那几次，现在「规划 2 + 证据 1 + 答复 1 + 评审 1 = 5」对得上。
3. **观察表看不出失败的先后**：重规划后新计划从第 1 步重跑，成功与失败分两个列表打印会把第2轮的成功排在第1轮的失败前面。改成按「第几轮 → 第几步」统一排序，并加一列「轮」。
4. **执行终止时渲染出了假的证据结论**：`board.evidence` 是空字典，`sufficient=False` 会被渲染成"证据不足"。改成证据没跑过就如实写「（未发生，执行阶段已终止）」。
5. **`main.py` 顶层没有 `import os`**：单元20 的 `/plan` 与单元21 的 `/agents` 都用到 `os.getenv`，一跑就 `NameError`。已在顶层补 `import os`（顺手修掉单元20 那个潜伏的同类问题）。
6. **真实模型演示不到"评审拒绝"**：真实模型不会故意写出不合格的草稿，所以 `revise`/`reject`/`gap`/`abort` 四个场景做**故障注入**（强制用剧本），并在输出里标注「（故障注入：草稿与评审结论用剧本，真实模型不受影响）」。
7. **场景标题把目标印了两遍**（收尾复核时发现）：`render_scenario` 的标题行写了「【…】目标：X」，紧接着 `render_result` 的第一行又写「目标：X」，`/agents demo` 每个场景开头都重复一遍。改成标题只印场景名，目标交给 `render_result`；并补 1 项回归（`test_scenario_header_prints_the_goal_once`，断言目标只出现一次），单元21 测试 54 → 55 项，全库 751 项。证据文档已用脚本重新生成。

### 本日修出的问题（单元22）

1. **复核不通过就立刻收尾，多轮退化成单轮**：第一版管理器一看到评审员发言就 `return`，于是 `rounds > 3` 完全没有意义，`轮次受控` 也无从演示。改成**不通过继续下一轮**（执行员看到复核意见再改一版），只有「通过 / 轮次用完 / 成本用完」三种收尾——现在 `revise` 场景真的跑出了 7 条消息、2 次复核、2 版草稿。
2. **角色标记会误命中群聊记录**：剧本模型按整段文本找「【角色：规划员】」，而群聊记录里写着「规划员：…」，评审员那一轮被认成规划员，返回了一段规划当成复核结论。改成**只在 system 消息里认角色**，数据仍然在 human 里取。
3. **发起者那条把证据 JSON 印了两遍**：消息流 1152 字里有 1000 字是证据 JSON，和上面「平台工具证据」段完全重复。改成渲染时只留摘要并注明「原文保留在消息记录里」，正文本身不动（消息记录仍是完整的）。
4. **成本演示值是靠实测标定的，不是猜的**：先跑出「发起者 720 + 规划 78 + 执行 124 = 922」这个真实数字，才把演示预算定在 900——刚好"发起者+两位"撞线、轮次还留一格，否则演示不到"钱先用完、轮次还有余"这个对照。
5. **`AgentSpec` 漏了 `tag` 字段**：三个角色构造时少传一个位置参数，模块一 import 就 `TypeError`。补上后顺便让 `ROLE_TAGS` 与角色表共用一份定义，不再两处手写。
6. **验收里把 `review`（单个字典）当次数用**：`check_standards` 想统计"复核了几次"，早期写成了对 `collab.review` 取长度。改成管理器维护 `verdicts` 列表、协作结果带 `review_history`，多轮时能逐次列出"第1次不通过 → 第2次通过"。
