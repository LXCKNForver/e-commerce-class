## 完成情况（2026-10-30 提前完成，按任务卡日期记在 11-03 日报）

**状态：已完成。** 分析入口是 `main.py` 的 `/data [参数]`；核心在 `app/data_agent.py`（守门 → 选口径 → 校验 → 统计 → 解释 → 数字核验），课堂编排在 `app/data_lab.py`。最关键的一条——**不执行任意生成代码**——是靠两件事一起保证的：模型两次发言都不碰数据本体，只输出一个 JSON 口径；口径里的算子只能从 8 个固定算子（`count / sum / mean / max / min / group_count / group_sum / group_mean`）里挑，字段只能从 8 个可分析字段里挑，真正做加法的是 `compute()` 里写死的分支。`app/data_agent.py` 里没有 `eval(` / `exec(` / `__import__(`，有一条测试用 `inspect.getsource` 盯着这件事；模型想塞一段表达式（比如 `sum(x for x in rows)`）进来，会被当成"未知算子"直接拒掉。

两次模型调用分工明确：**第一步选口径**时它只看数据字典、字段白名单和算子表，看不到一行数据、拿不到文件路径；**第二步解释结果**时它只看 Python 已经算好的结果，不许新增数字。解释写完还有一道 `check_explanation`：每个带单位的数字（`\d+(\.\d+)?\s*(元|%|单|条|行)`）都要能在结果里找到出处，找不到就点名列出。

真实 DeepSeek 下的一次完整分析（问题：各类售后问题的工单分别有多少单）：模型自己选了 `group_count(issue_type)`，Python 算出 6 组共 32 行，模型写出"物流异常 8 单（25.0%）、质量问题 8 单（25.0%）、退货退款 8 单（25.0%），三类合计占 75.0%…"，数字核验全部有出处，2 次模型调用、约 2 秒（实测 2.3 秒）。**截图需本人补齐。**

### 关键设计取舍

- **模型给的是「选择」，不是「代码」**。这是本单元最关键的一条，也是唯一不可退让的一条：让模型直接写 `pandas` 表达式确实更灵活，但那等于把执行权交出去。现在的做法是模型只输出 `{"metric": ..., "field": ..., "filters": {...}}`，Python 校验后走 8 个写死的分支。算子想塞表达式进来会被当成"未知算子"拒掉，源码里也没有 `eval(` / `exec(`。
- **两次调用严格分工，都不碰数据本体**。选口径那次只给数据字典和白名单（不给数据、不给路径）；解释那次只给已算好的结果（不给 CSV）。证据文档的第三节把两次提示词逐字留下来核对：是否含数据字典、是否含白名单、是否含统计结果，一列列摆出来，不靠猜。
- **空值与非数字既不静默当 0，也不整行丢弃**。当 0 会把均值拉低（实测 147.12 vs 162.34，差 15 元多），整行丢弃会让工单凭空少几单。现在的做法是：逐格记 `CellIssue`，数值聚合跳过并在算式里写明"跳过 3 行"，分组字段为空则归入「（空值）」组——行数一条都对得上（`32 = 29 参与 + 3 跳过`）。
- **结果必须能用计算器复核**。每个结果都带四行行数（总 / 筛选后 / 参与 / 跳过）、一条含除号的算式、以及前 5 行抽样（带筛选字段取值或分组归属）。这是"统计结果可复核"这条标准的落点，比只打印一个数字有用得多。
- **解释里的数字要回查出处，但只查带单位的**。`check_explanation` 的正则只匹配带 `元 / % / 单 / 条 / 行` 的数字，日期里的数字不算编造；允许的数字集合里还含"若干组相加"的合计与占比（≤8 组时枚举组合），否则模型说"三类合计占 75%"会被误判。
- **筛选后 0 行不等于失败**。`status=已关闭` 在表里根本没有这个取值，结果为空是正确的，但要说清楚为什么空：记为提醒、结果为空、不报错也不猜一个数。这条不在四条标准里，但它是"系统会不会骗人"的分水岭。
- **故障注入要标注清楚**。真实模型不会主动去读脏样本，也不会故意要越权字段，所以 `dirty / forbidden / missing` 三个场景强制走剧本，输出里明写「（故障注入：…真实模型不受影响）」，避免把演示效果当成模型能力。`overview / refund / handoff` 仍留给真实模型自己选口径。
- **旧实现一行没删**。单元23 只新增 `app/data_agent.py`、`app/data_lab.py`、`tests/test_unit23.py`、`scripts/generate_evidence_unit23.py` 与两份 CSV；`main.py` 只加了一条 `/data` 分支与帮助文本。
