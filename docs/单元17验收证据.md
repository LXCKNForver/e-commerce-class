## 七、边界核对

下面每一条都由 Python 在跑执行器**之前**或**执行过程中**拦下，
报错文案直接说明被拒绝的原因。

### 问题为空：守门在跑执行器之前，模型与工具都不会被触发

```text
ValueError: 问题不能为空
```

### 问题不是字符串：类型也要先看一眼

```text
ValueError: 问题必须是字符串，实际是：dict
```

### 步数上限写 0：构图时就报错，而不是跑到一半才发现

```text
ValueError: max_steps 必须大于 0
```

### 工具参数格式错：失败原因连同步号一起回填给模型

```text
第1步 lookup_faq（{'question_id': '123'}）成功=False 原因=lookup_faq.question_id 格式不正确：'123'
我们自己的日志里这一条被记为：error（失败也算一次调用）
```

### 清单外的工具：模型提了也执行不了，我们自己的日志里一条都没有

```text
第1步：提议 delete_collection({'name': 'faq'})；成功=False
定位信息：执行器未注册该工具，这一步没有执行任何查询
我们的执行日志条数：0（0 表示真的没执行）
```

### 步数上限触顶：不产出业务答案，也不偷偷多问一次模型

```text
停止原因：达到步数上限（未完成）
工具调用次数：2；模型决策次数上限：2
最终答案：（空）
执行器提示：Model call limits exceeded: run limit (2/2)
```

### 工具描述里没有内部细节：给模型看的只有用途与参数

```text
search_knowledge：检索本组制度或流程资料，返回片段和文件来源
  参数：['query']
lookup_faq：按本组 FAQ 编号从只读 SQLite 查标准答复与来源编号
  参数：['question_id']
compute_return_deadline：按签收日期与资料写明的退货时限，算出退货评估截止日期
  参数：['sign_date', 'window_days', 'basis_doc']
```

### 没配密钥时：真实模式当场报错，不静默降级到离线模型

```text
RuntimeError: 请先在项目 .env 中设置 DEEPSEEK_API_KEY，或改用 LLM_PROVIDER=mock
```

### provider 写错：不猜，直接说只支持两种

```text
ValueError: LLM_PROVIDER 只能是 mock 或 deepseek
```
