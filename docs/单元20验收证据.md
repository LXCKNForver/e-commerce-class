# 单元20 验收证据：Plan-and-Solve 规划（先出计划，再逐步执行）

本文件由 `scripts/generate_evidence_unit20.py` 抓取真实运行输出生成，步数、观察内容、重规划次数与终止原因都来自实际执行，不手写。

- 单元：20 Plan-and-Solve（4 课时）
- 本组选题：电商售后服务智能体（资料与工具沿用单元12/15）
- 第二、三节的计划由 `deepseek` 自己拆；其余段落用离线剧本模型（可复现）
- 第五、六、七节是**故障注入**：强制用剧本，真实模型会把 BAD 编号自己改对
- 密钥：只在 `.env` 里，输出统一 `sk-` 掩码

```

  规划器白名单： compute_return_deadline、lookup_faq、search_knowledge
  计划上限： 3 步；重规划上限： 1 次

Plan-and-Solve 流程（本组电商售后）

  目标（一句话业务问题）
    │ ① 规划：模型第 1 次调用，只输出 JSON（工具 + 参数 + 理由）
    ▼
  TaskPlan（1~3 步，工具只能在白名单里挑）
    │ ② 执行：Python 按 cursor 推进，走单元15 的注册表
    │     ├ 成功 → 记一条观察（步号 / 参数 / 真实返回值 / 耗时）
    │     └ 失败 → ③ 至多重规划一次（把错误与已有观察交回规划器）
    │             ├ 修订后跑完 → replanned=True，照常出答复
    │             └ 修订后仍失败 → 终止并报错（无答复）
    ▼
  ④ 答复：模型最后一次调用，只许用观察里出现过的事实

执行状态只在本次运行内保存（TaskPlan 在内存里，不落库）。

第1节要交的项目问题清单
问题	在哪一节验证
复杂目标怎么拆？	「买家 2026年12月1日签收的普通商品要退货：先查 E…」→ 3 步计划（第3节）
计划里的每一步真跑了吗？	轨迹逐条列工具、参数、真实返回值与耗时（第3节）
参数写错了会怎样？	BAD 编号被格式校验拒绝 → 重规划一次后跑完（第4节）
改了一次还错呢？	终止并报错，答复为空，不冒充完成（第4节）
编号合法但库里没有呢？	只返回「未找到」，是正常观察，不触发重规划（第4节）

Plan-and-Solve 概念对照（本项目里的实际含义）
概念	是什么	在本项目里落在哪
规划（Plan）	把目标拆成 1~3 个可执行步骤	make_plan()：模型只输出 JSON，不执行工具
求解（Solve）	按计划逐步调用真实工具	execute_plan()：走单元15 的注册表
观察	工具返回的真实结果	StepObservation：第几步、参数、返回值、耗时
重规划	失败后把错误交回规划器改一次	replans 上限 1；改完从第一步重跑
终止	修订后仍失败就报错	PlanAborted：状态 aborted、答复为空
计划 vs 记忆	计划只在本次运行；记忆跨轮	TaskPlan 不落库（与单元19 相反）
```

## 十、边界与注意事项（本单元核对过的地方）

| 情况 | 处理 |
| --- | --- |
| 目标为空 / 纯空白 / 非字符串 / 过短 / 超长 | validate_goal 拦在问模型之前，一次规划都不发 |
| 模型返回的不是 JSON | 直接报错「规划结果不是约定的 JSON」，不把任意文本当计划 |
| 计划步数不在 1~3 | 报错；上限约束调用成本，也防止超长计划 |
| 工具不在白名单 | 报错；模型只能挑注册表里已有的名字 |
| 参数类型不对（含 bool） | 报错；JSON 的 7 与 '7' 放行，格式交给执行时的正则 |
| 工具执行失败（格式 / 资料里没这个天数） | 记一条失败 → 重规划一次 → 从第 1 步重跑 |
| 重规划后仍失败 | PlanAborted：状态 aborted、答复为空、不调总结模型 |
| 编号格式合法但库里没有 | 返回「未找到」，是正常观察，不触发重规划 |
| 已成功步骤的观察 | 重规划后仍在列表里（审计证据），不会被冲掉 |
| 执行状态落盘 | 不落：任务卡明写只在本次运行内保存，与单元19 的长期记忆相反 |
