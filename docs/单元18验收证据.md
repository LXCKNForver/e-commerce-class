```text
长度不足（'退'）	已拒绝：问题至少 2 个字，实际只有 1 个；步骤表新增 0 条
超出长度（'退货退货退货退货退货退货退货退货退货退货退货退货…（共 130 字）'）	已拒绝：问题最多 120 个字，实际 130 个；过长会撑爆证据窗口；步骤表新增 0 条
不是字符串（123）	已拒绝：问题必须是字符串，实际是：int；步骤表新增 0 条
```

两处要看数字：兜底与无证据这两条路径的**模型调用都是 0 次**——不是「调了模型让它别乱说」，
而是压根没进生成那一步；无效输入那几行的「步骤表新增 0 条」说明守门建图之前就拦下了。

## 七、换模型不换编排

```text
模型：离线编排模型（只摘录证据，不生成新事实）

兜底答复：这个问题不在本工作流已登记的处理范围内，为避免误导，我不做猜测性回答。已按安全兜底转人工，请补充问题类型（编号查询 / 退货时限 / 售后政策）后重试。
```

同一套工作流、同一批资料，只把模型换成离线编排模型：路由结果、分支判定、兜底的

## 八、边界核对

下面每一条都由 Python 在跑工作流**之前**或**取证据过程中**拦下，
报错文案直接说明被拒绝的原因。

### 问题为空：守门在跑工作流之前，既不检索也不调模型

```text
ValueError: 问题不能为空
```

### 问题不是字符串：类型也要先看一眼

```text
ValueError: 问题必须是字符串，实际是：dict
```

### 库里没有这个 FAQ 编号：查不到就是查不到，不返回像答案的东西

```text
问题：EC-FAQ-09 的标准答复是什么？
分支：faq（FAQ 编号 → 只读 SQLite 精确查）
判定理由：问题里出现了 FAQ 编号 EC-FAQ-09，按编号精确查比按语义查准
取证据：lookup_faq；有证据=False；库里没有编号 EC-FAQ-09 这一行：查不到就是查不到，不返回像答案的东西
来源：（无）
模型调用：0 次；模型：ChatDeepSeek deepseek-chat（真实调用）
停止原因：资料不足（有分支但没取到证据，未调用模型）
摘要：（没有证据，不做摘要）
答复：资料不足：本组资料里没有能支撑这个问题的内容，不做推测，建议转人工核实。
```

### 日期不合法：算不出日子就不算，也不让模型口算

```text
问题：2026年13月45日签收的普通商品，退货评估最晚到哪天？
分支：deadline（签收日期 → 检索时限原文 → Python 算截止日期）
判定理由：问题里既给了日期（2026年13月45日）又在问「最晚」，需要先查时限再算日子
取证据：search_knowledge；有证据=False；问题里的日期不合法（如 13 月 45 日）：算不出日子，不猜
来源：（无）
模型调用：0 次；模型：ChatDeepSeek deepseek-chat（真实调用）
停止原因：资料不足（有分支但没取到证据，未调用模型）
摘要：（没有证据，不做摘要）
答复：资料不足：本组资料里没有能支撑这个问题的内容，不做推测，建议转人工核实。
```

### provider 写错：不猜，直接说只支持两种

```text
ValueError: LLM_PROVIDER 只能是 mock 或 deepseek
```

### 未显式指定 mock 时的模型身份：真实模式缺密钥当场报错，不静默降级

```text
RuntimeError: 请先在项目 .env 中设置 DEEPSEEK_API_KEY，或改用 LLM_PROVIDER=mock
```
