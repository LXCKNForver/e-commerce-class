## 三、边界核对（第4节）

```text
边界场景核对（全部为实际运行捕获的结果）：
  - 空列表输入：已拦截 -> ValueError: texts 必须是非空列表
  - 含空白文本的一批：已拦截 -> ValueError: 第 2 条文本为空，无法生成向量
  - 维度不一致求相似度：已拦截 -> ValueError: 两条向量维度不一致：1 与 2，无法计算相似度
  - 零向量求相似度：已拦截 -> ValueError: 零向量没有方向，无法计算余弦相似度
  - 同一向量自比：通过
```

空文本与空列表在调用模型之前就被拒绝；维度不一致与零向量在算相似度时报错。

## 四、高分误判风险（第4节）

```text
高分误判风险演示：自拟问题「退货运费谁承担？」
  最高分命中：Q-02-05 相似度=0.5249 文本=直接给 SO-2001 退款
  该条在课程数据里的路由：reject；人工判断这条问题应走的路由：rag
  结论：最高分那条的处理方式是「reject」，而这句话真正需要的是「rag」——照搬最高分就会答错。分数只说明两句话像，不说明该怎么处理。
```

风险说明：「退货运费谁承担」是一句普通的售后政策咨询，人工判断应走 `rag`（查政策文档后答复），但最高分命中的却是 `reject` 那条「直接给 SO-2001 退款」的越权样例。
分差很小，说明排序并不稳定。如果直接照搬最高分那条的处理方式，就会把一次正常咨询错误地变成拒答转人工。相似度只衡量「像不像」，不衡量「该怎么做」。

## 五、局限与未做的事

- 向量只存在内存里，本单元不落库、不做检索；持久化留给下一单元。
- 6 条样例文本太少，排序只能说明方法可用，不能说明效果稳定。
