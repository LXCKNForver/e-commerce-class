## 一、三种格式的解析单位与解析清单（0–17 分钟）

同一个 `parse_file()` 处理三种格式，差别只在「一条记录是什么」：Markdown 是一整篇文档、
PDF 是一页、CSV 是一行。表头不算记录，所以 CSV 的行号从 2 开始，与人在表格里看到的行号一致。

```text
三种格式的解析单位（0–8 分钟）
格式	解析单位	一条记录是什么	注意事项
.md	文档（整篇）	一整篇 Markdown 一条记录	课程样例短，本单元不再讲分块
.pdf	页	每一页各一条记录	按可复制文字提取，扫描件无文字层需先 OCR
.csv	数据行	每个数据行一条记录	表头不算记录，行号从 2 起，与表格行号一致

本项目实际解析条数：.md 3 条；.pdf 1 条；.csv 3 条
```

location（这份文件里的第几页/第几行/第几篇）**。稳定 ID 由「项目 + 文件名 + 位置类型 + 位置」拼成，

## 五、按项目计数：隔离是查出来的，不是分库分出来的

两个项目的资料写在**同一个集合**里。既然在同一个集合，为什么另一个项目的 7 条不会算进本项目？
下面直接数一遍：

```text
数据库目录：D:\pycharm\Agent\e-commerce-class\.chroma_unit12
集合：after_sale_parsed_materials
库内总数：14 条
  project_id=e-commerce-after-sales：7 条
  project_id=travel-expense-demo：7 条
  project_id=not-a-project：0 条
```

答案是三条，缺一条都不成立：

1. **稳定 ID 就不同**：ID 以项目标识开头（`e-commerce-after-sales:…` / `travel-expense-demo:…`），
   同一个文件在两个项目里也是两条不同记录，不会互相覆盖，也不会重复计数。
2. **每条记录都带 `project_id` 元数据**，写入时一起落盘，不是事后补的。
3. **计数与检索都带 `where project_id` 过滤**，另一个项目的记录在查询条件之外；
   写一个库里根本没有的项目标识，结果就是 0 条——过滤条件确实在执行，不是碰巧数对了。

所以「另一个项目的数据不会计入本项目数量」不是因为分了两个库，而是因为**每条记录都记得自己属于谁**。

## 七、本单元没有做的事

- **不做 OCR**：扫描件没有文字层，`parse_file` 会如实报「PDF 没有可提取文字」，
  而不是编一段看起来像正文的东西出来。
- **不做分块**：Markdown 按整篇导入，分块是单元11 的内容；本单元只解决「三种格式怎么变成同一种记录」。
- **不生成回答**：本单元到入库为止，问答留给单元10 的 RAG 流程。
- **不做表格结构还原**：CSV 一行压成一段「字段：值」，够检索用；要保留列语义得另建字段，
  那属于结构化入库，不在这次练习范围。
