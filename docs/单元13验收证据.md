## 六、五个指标各在检查什么

| 指标 | 谁给的 | 检查什么 | 注意 |
| --- | --- | --- | --- |
| Precision@3 | 规则 | Top-3 里有多少条命中了人工标注的来源（按条数计） | 同一文件的多行 CSV 各占一个位置，全命中也要一条条算 |
| Recall@3 | 规则 | 标注的相关来源被找回了多少（按去重文件计） | 重复片段不虚增覆盖率；Recall 低说明直接证据没进 Top-3 |
| Context Precision | 模型 | 排在前面的检索文本里有多少真正有用 | 量的是排序质量：有用的有没有被排到前面 |
| Context Recall | 模型 | 参考答案里的事实能否被检索到的文本支撑 | 量的是证据覆盖：缺了哪条证据就答不完整 |
| Faithfulness | 模型 | 回答里的每个事实能否在检索文本里找到出处 | 忠实度不等于正确率：答非所问但句句有据仍会得高分 |

一句话区分：前两个是**排序/覆盖的客观计数**（人工先标注了相关来源），
后三个是**让模型读文本后给的主观判断**（参考答案当尺子）。
Faithfulness 高只说明「句句有据」，不等于答对——答非所问但每句都能在
检索文本里找到出处，照样拿高分。所以它必须和 Recall@3 一起看：
Recall@3 低说明证据没找全，此时 Faithfulness 再高也只是自洽。

- **本题标注来源**：DOC-02-01-普通商品退货规则.md、常见售后问题.csv
- **归因在排序不在召回**：Recall 满分说明直接证据都进了候选，丢分是因为一条不相关的资料占了 Top-3 里的位置——「资料不足」不是没检索到，而是排序里混进了噪声。
- **Faithfulness 仍然接近满分**：模型没有编造，它引的每句话都来自检索到的文本；忠实度不等于正确率。
- **可改进的两处**：① 检索侧——按 `doc_type` 过滤掉「受理材料清单」这类凭证资料，或把 top_k 放宽到 5 后接单元11 的分块 + BGE 重排；② 生成侧——要求「资料未覆盖时明确说资料不足」，避免用相邻话题的资料拼出看似合理的答复。

## 八、边界核对

评估链路要能容错。下面每一种不合法输入都**在调用模型之前**被挡住，并且报错能指出是第几题、缺什么。

### 未配置密钥就跑 RAGAS 评审

```text
RuntimeError: 未配置 DEEPSEEK_API_KEY，无法运行 RAGAS 评审；请在 .env 里填写
```

### 评估题数小于 1

```text
ValueError: limit 必须大于 0
```

### 题集不足 3 道题

```text
ValueError: 完成标准要求至少 3 道题，当前只有 1 道
```

### 第 3 题缺少参考答案

```text
ValueError: 第 3 道题缺少字段：reference_answer
```

### 题目没有标注任何相关来源

```text
ValueError: 每道评估题至少标注一个相关来源
```
