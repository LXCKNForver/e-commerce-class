本文件由 `scripts/generate_evidence_unit19.py` 抓取真实运行输出生成，条数、编号与结论都来自实际执行，不手写。

- 单元：19 对话记忆（4 课时）
- 本组选题：电商售后服务智能体（资料与工具沿用单元12/15/17）
- 真实模型段落的模型：`deepseek`；标注「离线脚本模式」的段落用离线剧本模型跑
- 密钥：只在 `.env` 里，输出统一 `sk-` 掩码

```

- 「刚才那项」到底指什么？ → 指代解析落到具体编号并打印（第2节「刚才那项，买家要在签收后多久内申请退货评估？」）
```


## 四、第3节：三种记忆模式横向对比

```
三种记忆模式对照：
模式	这一轮带进模型的内容	进程重启后	额外模型调用	代价

摘要记忆（summary）	一句压缩摘要	消失	每轮 1 次	省上下文，但细节可能丢（编号由程序补回兜底）
```

## 五、第3节：长期记忆跨进程召回（两个独立 Python 进程）

```
【进程一：写入记忆】
进程一（写入）：本轮工具 ('lookup_faq',) ；停止原因 正常完成
进程一（写入）：长期记忆条数 1

【进程二：全新进程，只读】
进程二（只读）：库里该会话的记忆条数 = 1
进程二（只读）：按第2轮问句召回 = 1 条
   - 第1轮 用户：EC-FAQ-01 的标准答复是什么？｜助手：（离线脚本模式：以下为工具返回的原文摘录，不生成新事实，最终以人工复核为准） - 第1次工具返回：{"storage": "SQLite（结
进程二（只读）：完整历史 = 0 条
进程二（只读）：对话摘要 = ''
```

两个进程之间没有任何内存共享：进程二读到的东西只能来自磁盘。同一时刻它的完整历史是 0 条、摘要是空的——完整历史与摘要只活在内存里，长期记忆落盘，这就是两种记忆的分界。

## 十、边界与注意事项（本单元核对过的地方）

| 情况 | 处理 |
| --- | --- |
| 空会话 ID / 含空格 / 中文 / 超长 | 读写之前就被 SESSION_PATTERN 拦下，连库都不碰 |
| 空问题 / 纯空白 / 非字符串 | validate_question 拦在入口（与作答同一个校验） |
| 未知记忆模式 | 只认 buffer / summary / vector / hybrid 四种 |
| 答案为空或触顶的轮次 | 不写记忆——失败轮不能变成下一轮的事实 |
| 摘要写漏编号 | 程序生成时补回并标注，不假装模型记得 |
| 长期记忆长期累积 | /memory new 会话名 或 clear_session 换一批演示 |
| 两个会话同时用 | 键前缀 + 库端 source 过滤，双保险 |
| 记忆与知识库混用 | 两个库目录严格分开，召回内容一律带「仅作语境」前缀 |
